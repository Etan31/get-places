Initially assumed this was a 500 response, but the Network tab showed **200 OK** - correct once you factor in the streaming design: `scrapeController.js` calls `response.flushHeaders()` (committing status 200) before any scraping happens, then streams NDJSON events; an error mid-stream can only ever add an `{type: 'error'}` line, it can no longer change the already-sent status code. The client got *only* the error event, no preceding `{type: 'status', message: 'Searching Google Maps...'}` - meaning the failure happened at the very first line of `runPlaceScrape` (`chromium.launch()`), before any scraping logic runs.
